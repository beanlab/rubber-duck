# Rubber Duck Working Session

Date: 2026-05-18 4:00 PM

## Summary

The discussion focused on two threads: a precision bug in the
imprecision-handling path, and a broader refactor for workflow usage
tracking. The preferred direction was to introduce a context-based
runner around `run_agent` so usage can be accumulated automatically
across steps and reported by model at the end of a workflow.

## Main Points

- Adding an "incomplete response" field caused the agent to confuse
  response incompleteness with rubric incompleteness.
- The current workaround is to handle imprecision in a separate
  subprocess, similar to the incorrect-answer flow.
- The workflow usage design should keep business logic separate from
  usage plumbing.
- A context manager around `run_agent` is the preferred approach for
  usage tracking.
- Usage should be aggregated by model, not only as one total.
- Session lookup helpers should be simplified to take the session ID
  directly where possible.
- Error handling should be moved closer to the source of failure.
- Pricing data can live in the Codex module and be reused by Pi.
- The mid-step model-switch limitation is acceptable for now and
  should be tracked in the backlog.

## Decisions

- Use a context-based workflow wrapper for usage tracking.
- Keep direct `run_agent` calls working for backward compatibility.
- Track totals per model and overall totals at context exit.
- Defer mid-step model-switch handling to a backlog item.

## Tasks

- Aggregate token usage and cost by model at workflow exit.
- Refactor session helpers to reduce duplicated path resolution.
- Move exception handling closer to the parsing source.
- Move pricing data into the Codex module.
