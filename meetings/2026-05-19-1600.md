Date: 2026-05-19 16:00 (America/Denver)

## Summary

Reviewed a PR that introduces an agent context manager and related
refactors, then discussed usage reporting, evaluation speed/cost, and
whether to keep YAML-defined workflows for non-coders.

## Main Points

- Meeting schedule and summer work goals: keep status quo for now; the
  process and what is "on the table" should be clearer by end of June.
- PR review: agent context manager is in place; suggested further
  simplification by pulling most `run_agent` logic out of the context
  class so the context class stays focused on bookkeeping.
- Usage reporting: reduce duplicated formatting and consider a single
  consolidated "usage summary" formatter.
- Longer-term usage UX: consider a configurable usage verbosity level
  (none, total only, by model, per step) and connect it to an existing
  verbose/debug flag.
- Evaluation performance: try smaller/faster models and compare speed
  and sufficiency; note that larger models can sometimes complete
  faster even if more expensive.
- Testing/evals: explore whether a scripted replay / eval loop could
  reduce manual regression testing for these interactions; note risk
  that "LLM-as-judge" may be too coarse for the nuance needed.
- YAML workflows: preference is code for real workflows (loops,
  conditions); YAML may still help non-coders for linear, repeatable
  tasks. Keep the YAML-removal branch around for now.
- Infra note: Discord build notifications broke due to a channel
  change; Overduck was restarted to pick up the new link.

## Decisions

- Keep the current meeting schedule/status quo for now.
- Do not remove YAML workflows yet; keep the cleanup/removal branch
  around until after further validation with non-technical users.
